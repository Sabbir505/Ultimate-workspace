**Method.** Every claim below was checked against the actual code and configuration in this repository (branch `feat/companion-pet`, app version 0.4.2). Nothing was taken from framework assumptions. ## Plain-language overview

Relay is a large, local-first Windows desktop app (Tauri 2 + React) that hosts AI coding agents. It is genuinely big: **198 Rust files (123,518 lines)** on the backend and **414 TypeScript files (86,843 lines)** on the frontend, exposing **320 IPC commands** to the UI, with **49 SQLite tables**, **6 bundled agent harnesses** plus a dynamic ACP protocol layer, a native-browser-pane system, scheduled automations, local AI model support, speech-to-text/text-to-speech, a mobile companion protocol, and its own self-improvement engine.

The overall picture is **unusually well-engineered for its size**: the code is heavily documented with real design rationale in comments, the big performance problems have actually been fixed (event-driven git watching, PTY output batching at 16 ms / 64 KB, requestAnimationFrame token coalescing, list virtualization, lazy-loaded heavy libraries), and the core business logic (cron scheduling with exactly-once catch-up, context compaction, plan-mode gating, checkpoint restore, OAuth with PKCE, failover idempotency) is implemented correctly with edge cases handled and tested. **2,108 automated tests pass**: 1,075 Rust library tests (0 failures) and 1,033 frontend tests (0 failures).

But the audit found **one item that needs action today** and a cluster of related weaknesses that share one theme: *the app's renderer is trusted more than it should be, and several surfaces compound a renderer compromise into full machine control.*

1. **A real GitHub OAuth token is committed in the source** (`src-tauri/src/connectors/oauth.rs:1322-1327`, prefix `gho_` — the GitHub-documented format for OAuth app user tokens, captured from "the first live GitHub connect"). Treat it as leaked: revoke it. (Critical)
2. **The webview is a big attack surface by configuration**: the main window's CSP allows remote scripts from cdnjs.cloudflare.com, connections to any HTTPS host, and the `opener:allow-open-path` capability lets the renderer open any local path with no scope. Several IPC commands then turn a compromised renderer into arbitrary code execution: `spawn_shell` runs any frontend-supplied command string through `cmd.exe /C` with optional project-secret injection (pty_cmds.rs:189-242), the MCP gallery accepts an arbitrary command+args+env as a "custom server", and `set_llama_server_path` spawns any exe the frontend names. (High, by composition)
3. **Automations can act unattended at full permission**: scheduled turns force `full_auto`, can include `--dangerously-skip-permissions` for Claude Code, and — with "run while closed" enabled — a Windows Task Scheduler task (`RelayAutomations`, every minute) executes due agent prompts even when the app is closed. Since the chat model itself can create automations (gated only by an approval card in safer modes), this is a persistence mechanism an injected prompt can reach. (High, by design — but the design deserves a hard look)
4. **Cost governance is advisory**: budgets only emit alerts — nothing aborts a run or blocks a send — and the built-in price table is hardcoded (researched 2026-07, so already missing newer models) with a cache-read rate of 0.1× input for *all* providers, which under-prices OpenAI cached tokens 5× versus OpenAI's published 50% discount. (Medium)
5. **Shipping is Windows-only**: NSIS is the only bundle target, the sidecar binaries in `binaries/` are Windows `.exe`s, the bundled LibreOffice is Windows-only, and one-click STT install is Windows-only — even though substantial macOS/Linux implementations exist in the source (vibrancy, keyring, browser panes, PID probes). The installer is also unsigned (no Authenticode), so SmartScreen will warn. (Medium/High for any non-Windows ambition)

Smaller verified items: the mobile pairing token (which gates full remote chat control) is stored in plaintext in the settings table; partial assistant text is lost if the app quits mid-stream; per-session checkpoints grow without a cap; and there are structural debts (two-and-a-half parallel chat pipelines, a 3,739-line zustand store, one global DB mutex).

Nothing in the audit found evidence of SQL injection, zip-slip, XSS in message rendering, or plaintext API-key storage — those areas checked out clean, with defense-in-depth actually present.

## 1. Architecture — **Proved** (structural debt: Medium)

**What it is.** Tauri 2 (Rust) + React 18 + Vite 5 + zustand + SQLite (WAL). The layering is real and consistent: `src/lib/ipcCore.ts:1-45` wraps `invoke`/`listen`; 19 domain IPC modules in `src/lib/ipc/`; commands in `src-tauri/src/commands/` delegate to managers (`chat::ChatManager`, `pty::PtyManager`, `agent_sessions::AgentSessionManager`, `browser::BrowserManager`); persistence in `src-tauri/src/db/` (49 tables: 46 `CREATE TABLE` in db/mod.rs + 3 in db/cost.rs, WAL + 5 s busy_timeout at db/mod.rs:176,181).

**Verified end-to-end chain (agent harness send):** `sendAgentChatMessage` (src/lib/ipc/artifacts.ts:572) → `send_agent_chat_message` (commands/agent_cmds.rs:35-89) → `AgentSessionManager::send` (agent_sessions/mod.rs:392-476, global session map + persisted `cli_session_id`) → adapter registry of 6 harnesses (`harness_adapters/mod.rs:193-212`: claude_code, kimi_code, opencode, pi, omp, commandcode) plus dynamic `acp:<name>` agents (agent_sessions/mod.rs:717) → parsed stdout → `emit_token` → typed `Channel` or `app.emit("chat:token")` → `useChatEvents.ts:71-77` → `useChatStore.onToken`.

**Three event-return mechanisms coexist** (global `app.emit`, typed per-session token channels with fallback — chat/stream_events.rs:1-24, typed PTY byte channels with 16 ms/64 KB frames — pty/mod.rs:239-244).

**Structural debt found (Medium):**
- **Parallel chat pipelines.** World A: provider-HTTP chat mode (`chat/dispatch.rs` 3,135 lines + `chat/commands/send.rs` 2,129). World B: harness-CLI sessions (`agent_sessions/mod.rs` 3,117 + re-implemented tool/event translation in `handlers.rs`). World C: mobile re-routes WS messages through a third send path (`mobile/session_chat.rs:171-196`, comment at :393). Both worlds write the same tables and emit the same event names (db::add_chat_message at send.rs:642 and agent_sessions/mod.rs:542,1079).
- **God store.** `src/state/chat.ts` is 3,739 lines in one zustand store, with module-level mutable caches escaping it (chat.ts:216-224, 500).
- **Single DB mutex as chokepoint.** `DbState(Arc<Mutex<Connection>>)` (lib.rs:57); lib.rs:274-277 itself documents the frozen-window hazard for non-async commands.
- **Layering inversion.** The agent layer reaches into chat internals: `crate::chat::compaction::COMPACTED_PREFIX` (agent_sessions/mod.rs:1280), `process_attachments` reuse (agent_cmds.rs:62).
- **Contract docs exist and are honored**: `docs/ai-context/CONTRACT.md`, `docs/ai-context/PRD.md`, cited from types.rs:4, lib.rs:4-5, db/mod.rs:1, commands/mod.rs:2.

## 3. Security — **Weak** (Critical)

### 3.1 Critical — leaked live GitHub OAuth token in source
`src-tauri/src/connectors/oauth.rs:1322-1327` (inside `#[cfg(test)]`): a test fixture embeds `access_token=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&scope=read%3Aorg%2Cread%3Auser%2Crepo%2Cuser%3Aemail...` with the comment "The EXACT body GitHub's OAuth App token endpoint returned for the first live GitHub connect". Verified against primary sources: `gho_` is the documented GitHub OAuth-app user-token prefix (docs.github.com REST API docs; github.blog "Behind GitHub's new authentication token formats"). Scope includes `repo` (read/write on all repos). The token's current validity was deliberately **not** tested (using a found credential is out of bounds) — treat as compromised and revoke. Severity: **Critical** (credential leak; trivially fixable by truncating the fixture).

### 3.2 High (composite) — renderer trust by configuration
- **CSP** (`tauri.conf.json:30`): `script-src 'self' https://cdnjs.cloudflare.com` (remote scripts in the privileged window), `connect-src ... https:` (any HTTPS host), `img-src ... https:`, `style-src 'unsafe-inline'`. A test asserts cdnjs is present for live previews (src/test/csp.test.ts:28-32) — deliberate, but it makes any future HTML-injection bug in the main window remotely exploitable and trusts cdnjs as a single point.
- **`opener:allow-open-path` unscoped** (capabilities/default.json:22): the desktop schema describes this permission as enabling `open_path` "without any pre-configured scope" — any window in the capability set (`main`, `browser-*`, `oauth-*`) can open any local path with the OS handler. Mitigation verified: capabilities are `local: true`, so remote pages in browser panes don't hold them (gen/schemas/capabilities.json).
- **Positives verified:** no `withGlobalTauri`; zero `window.__TAURI__` uses; `fs` scope limited to `fs:allow-read-text-file`; updater runtime verifies signatures against the baked-in pubkey with no bypass (commands/updater_cmds.rs).

### 3.3 Clean areas (checked, no issue)
- **Secrets at rest**: key names only in SQLite with `keyring:v1` marker; values in the OS keychain (secrets.rs:1-30, 88-89, 169-177). Chat API keys never returned to the frontend (`has_key: bool` only, chat/commands/api_keys.rs:24-58). The XOR fallback is `cfg(not(any(windows, macos, linux)))` — dead code on every shipped target (secrets.rs:249-263).
- **SQL injection**: 7 `format!`-built SQL sites in db/, all interpolating only static const column lists; FTS5 user tokens sanitized to quoted-prefix OR terms and bound as `?1` (db/memory.rs:240-262). No concatenated user input found anywhere.
- **XSS**: markdown via react-markdown without rehype-raw; the 4 `dangerouslySetInnerHTML` sites all pass through DOMPurify with script/iframe/form forbidding (src/lib/sanitize.ts:35-52); model HTML previews render in `sandbox="allow-scripts"` iframes *without* `allow-same-origin` (ArtifactPreviewPane.tsx:443-472) — opaque origin, no Tauri IPC.
- **Command injection**: git and GitHub integrations use argv arrays (git.rs:31, github.rs:140); no user/DB string is interpolated into `cmd /c` / `sh -c` outside the deliberately-shell surfaces covered in §4.
- **Path traversal**: `read_file_text` canonicalizes and checks against project-root allowlist (commands/data.rs:392-470); artifact preview/download/external-open re-check resolved paths against scope roots (chat/commands/preview.rs:47-128, 769-808); skill commands never join frontend input into paths (scan-by-slug, installed_skills.rs:407-418); zip import sanitizes every artifact filename (chat/export.rs:551-565).
- **Mobile relay & browser MCP bridge**: loopback-only binds, 256-bit tokens with constant-time compare (`subtle::ConstantTimeEq`, mobile/relay.rs:490-499), XChaCha20-Poly1305 frames with counter nonces (relay_crypto.rs:20-107); the browser-MCP handshake file contains only `{port, pid}`, never the token (browser_mcp.rs:49-72).
- **OAuth**: PKCE + state validated, one-shot loopback capture on fixed registered ports, tokens straight to keychain, only code *length* logged (connectors/oauth.rs:1-16, 425-427, 546).
- **Weak notes:** mobile pairing token stored plaintext in settings (mobile/relay.rs:236-237 — verified directly: `db::set_setting(&conn, "mobile.pairing_token", ...)`); a legacy plaintext pairing mode remains (mobile/relay_requests.rs:117-130); `set_setting` accepts arbitrary keys so the renderer can overwrite the pairing token (commands/data.rs:22-30); `import_sidebar_art` copies any `*.png/jpg/...` path from the frontend into app data (image-only arbitrary read, commands/appearance_cmds.rs:57-105); updater pipeline mismatch (`createUpdaterArtifacts: false` vs active updater) — see §6.

## 4. Privileged areas — **Weak** (High)

Ranked surfaces, each verified at the cited lines:

1. **`spawn_shell` — unallowlisted shell, optional secret injection** (High). `commands/pty_cmds.rs:189-242`: frontend supplies any `cwd` + `command` string; executed via `cmd.exe /C <command>` (or `$SHELL -lc`); can inject project secrets as env vars (`inject_secrets_project_id`). The code's own comment (215-221): *"Callers are responsible for not letting untrusted model output flow into this argument."* A compromised renderer = arbitrary command execution + secret exfil. NUL-byte guard present (223-227).
2. **Unattended full-auto automations + OS persistence** (High, by design). automations.rs:6-8: *"Runs force `full_auto` permission because unattended turns can't answer prompts"*; Claude spawn includes `--dangerously-skip-permissions` when the session mode is bypassPermissions (agent_sessions/claude.rs:84-86 — verified directly). With "run while closed", `schtasks /Create /TN RelayAutomations ... /SC MINUTE /MO 1` → hidden VBS → `relay-automation run-due` (automation_task.rs:113-143, 212-250) — agent prompts execute every minute even with the app closed. The chat model can create automations with arbitrary `cwd`/prompt, gated only by an approval card in safer modes (dispatch.rs:1597-1599: *"the card is the only guard on create/delete/run-now in the safer modes"*).
3. **MCP gallery custom servers → arbitrary child process** (High). `mcp_gallery.rs:559-596` accepts frontend-supplied `command`/`args`/`env` with only non-empty checks; spawned (wrapped in `cmd.exe /C` on Windows, :312). Catalog entries additionally run unpinned `npx -y`/`uvx` (latest from npm/PyPI at spawn time). Tool calls from MCP servers are permission-gated (dispatch.rs:2118-2127), and the relay-tools MCP path enforces a 20-entry whitelist that excludes all mutating tools (mcp_tools_bridge.rs:13-20).
4. **Skill writes into agent auto-load directories** (Medium-High). `installed_skills.rs:87-92, 433-466` writes `SKILL.md` into `~/.claude/skills` and `~/.agents/skills` via plain IPC commands; content unvalidated; those files are instructions future coding-agent sessions auto-load — a prompt-injection persistence sink. The self-improvement engine's `auto` autonomy tier can write these without the user (improve_engine.rs:735-739, capped 1/24 h with eval gates ≥95% pass and canary rollback, improve_engine.rs:443-560).
5. **`set_llama_server_path` — arbitrary exe launch** (Medium). `chat/commands/llama_sidecar.rs:232-266`: validation is `p.is_file()` only; the binary is later spawned (chat/local_models.rs:755).
6. **`test_automation_webhook` — unfiltered outbound POST** (Low-Medium/SSRF). `automation_task.rs:255-274` POSTs to the setting-configured webhook URL with no scheme/host filtering; user-configured, not model-set.
7. **Well-gated, verified:** chat `run_shell` tool is stripped from the schema under read_only and requires explicit approval in every mode except FullAccess (chat/permission.rs:259-262; dispatch.rs:2136-2159 registers a pending approval and awaits it); plan mode blocks every mutating tool before approval (chat/plan.rs:311-320, enforced at dispatch.rs:1966); checkpoints restore takes a safety snapshot first and never runs `git reset --hard`/`clean` (checkpoints.rs:245-251; git.rs:1148-1172 validates every repo-relative path before `remove_file`); sidecar downloads that execute code are pinned AND SHA-256-verified (whisper b4938 at stt.rs:708-717, 851-873; sherpa GPU bundle + cuDNN wheel at tts_gpu.rs:57-69, 469-478); model downloads attach the HF token only to huggingface.co hosts (local_model_market.rs:238-256); browser panes give visited pages no Tauri internals and validate their 3-message callback bridge against per-action nonces (browser.rs:1284-1364); `remove_dir_all` call sites reviewed — each is scan-matched, scope-gated, or app-temp (top sites: installed_skills.rs:477 with SKILL.md guard; chat/tools/fs.rs:334 behind permission + scope gates; chat/office.rs:1360/1412 app-temp).
8. **GitHub integration** (Low-Medium): connector token carries `repo` scope (read/write all repos); commands can create PRs and submit reviews (github.rs:238-270, 347-370); no merge endpoint is called anywhere.

## 6. Deployment — **Weak** (Medium)

**Present and verified:** `.github/workflows/build.yml` (199 lines) — tag `v*` → Windows build (Python + LibreOffice staging, sidecar builds, `npm run tauri build`) → release job restores `TAURI_SIGNING_PRIVATE_KEY`, runs `make-latest-json.mjs` (which signs the exe via `npx @tauri-apps/cli signer sign`, builds `latest.json` with the signature) → GitHub Release. Plus a `check-macos` compile-only job. Updater endpoint matches the git remote (`github.com/Sabbir505/Ultimate-workspace`). Runtime update flow uses only the verifying plugin APIs with a single-flight guard (updater_cmds.rs). Desktop versions consistent at **0.4.2** across package.json / tauri.conf.json / Cargo.toml, with matching git tags and a maintained CHANGELOG.md.

**Findings:**
- **No Authenticode signing** (Medium): `bundle.windows` has no certificate config (tauri.conf.json:47-52); build.yml:6 says "producing an unsigned (Windows) installer" — expect SmartScreen/AV friction.
- **Updater artifacts signed out-of-band** (Low-Medium): `createUpdaterArtifacts: false` while `plugins.updater.active: true`. Verified against Tauri v2 docs: `createUpdaterArtifacts: true` makes the build emit signed artifacts; here the release job signs via CLI instead. Valid, but if the release job's sign step is ever skipped, updates fail closed ("no update") — a silent-fragility tradeoff, not a security hole (runtime verification is intact).
- **Mobile not deployable** (Info): `mobile/eas.json:2` "Scaffold only — no projectId yet"; mobile version 1.0.0 desynced from 0.4.2.
- **Hygiene** (Low): `.git` is 2.1 GB with ~141 MB blobs in history from previously committed runtimes; working tree carries ~205 GB `src-tauri/target` (likely junction double-count — partially verified) and stale `conduit-*` pre-rebrand sidecars in `binaries/`. Correctly ignored today: target/, dist/, node_modules/, binaries/, resources/ — 919 tracked files, **no `.env` files anywhere**; OAuth client secrets are injected at build time via CI env (build.yml:137-143) and compiled into the binary (documented in .gitignore comments).
- **Dev/prod parity** (no issue): dev resource fallback gated `#[cfg(debug_assertions)]` (lib.rs:123-131); vite port 1500 matches `devUrl`.

## 7. Jobs — **Proved** (Medium policy risk → §4)

All background-work mechanisms verified in code:

- **Automations scheduler**: 30 s tick (automations.rs:124); `next_fire` computes cron in **local time** via chrono `Local` (automations.rs:193-197); missed-while-closed runs fire **exactly once** on the next tick, not once per missed slot (documented at :12-15; anchor = `last_run_at`, and `record_status(skipped)` deliberately doesn't touch it — db/automations.rs:177); `MAX_RUN_SECS = 2 h` bounds hung runs; `catch_unwind` releases guards on panic.

Solid.

## 8. Business logic — **Weak** (core flows Proved; Medium findings)

**Verified correct (Proved):**
- **Cron math & catch-up** — see §7.
- **Compaction** (chat/compaction.rs): adaptive trigger 0.60→0.85 of context by window size (default 0.75; :46, 54-76); response headroom 512 tokens; pin last 6 exchanges (12 messages) verbatim, summarize the middle, one `[compacted context]` system row + pinned tail fed back (:377-415, 874-883); never compacts with nothing aged out (:404-407); summarizer input capped 12,000 chars/entry keeping head+tail; overflow-span map-reduced into ≤8 partials; `rebuild_from_raw` prevents summary-stacking; live user message excluded from supersession (:866). Failure → passthrough (safe direction).
- **Token counting**: real `/tokenize` for local models (compaction.rs:215-299); chars/4 heuristic for cloud — drift mitigated by forced compact-and-retry on provider context-overflow (chat/mod.rs:854-881).
- **Auto-routing & failover**: re-resolved per send; failover only on pre-stream retryable failures; *"Mid-stream failures NEVER re-route"* (chat/mod.rs:686-689); reconnect ladder gated on `tools_ran() == 0` so executed tools are never replayed (:823-851); user row persisted exactly once before the candidate loop (send.rs:639-653) — retries are idempotent.
- **Memory pipeline**: extraction every 3-5 assistant turns (worker.rs:30-31), secret-bearing candidates dropped not redacted (extract.rs:119-168), similarity gate 0.55 / auto-supersede 0.8 (model.rs:50, 59), injection capped at 2 core facts + top-4 recalled within an 800-token per-turn budget, wrapped in a "DATA, not instructions" fence (render.rs:17-35).
- **Plan mode gate**: `gate_denial` blocks every mutating tool before approval; approval raced-safe (dropped oneshot → treated as cancelled, plan.rs:497-556).
- **Checkpoints**: per-turn snapshots under `refs/relay/checkpoints/<session>/`; restore takes a safety snapshot of current state first — one-click undoable (checkpoints.rs:245-251); tree restore avoids `reset --hard` (git.rs:1148-1172).
- **Cost math**: formula `(input·in + cached·cache_read + output·out)/1e6` verified by the in-repo worked example = $14.10 (pricing.rs:53-70, 113-116); harness-reported cost preferred over estimates (cost_v2.rs:275); rollup cache invalidated by MAX(timestamp) markers + 10-minute bucket.
- **Title generation**: real LLM oneshot, max_tokens 32, failure → keep existing title (chat/commands/generators.rs:11-115).

**Findings:**
1. **Budgets are advisory only** (Medium). `commands/budget.rs:189-215` computes usage percent and **only emits** `budget:alert` + a mobile push. Nothing in the send path or dispatch calls it; no backend timer exists despite the doc comment "on a timer" (:151-153) — the only caller is the frontend on `cost:updated` (src/hooks/useBudgetEvents.ts:30-36). A run can blow through a budget indefinitely; checks also stop when no window is open. Also: month window computed in UTC epoch-day arithmetic while the comment says "local day boundary" (:160-167).
2. **Hardcoded, already-stale price table** (Medium). `harness_adapters/mod.rs:162-175`: rates "researched 2026-07" for 4 models. Verified against current primary sources: the four entries are accurate (opus-4-8 $5/$25; sonnet-4-5 $3/$15; haiku-4-5 $1/$5), but the table lacks the newer models that now exist (Sonnet 4.6, Sonnet 5, Opus 5) — anything unlisted falls back to provider-reported cost or is unpriced for in-app chat rows.
3. **Cache-read price 0.1× input for all providers** (Medium). `pricing.rs:31` hardcodes `cache_read_per_mtok: in_def * 0.1` while the adjacent comment claims "so OpenAI's 0.5× is preserved" — nothing preserves it. Verified against OpenAI's pricing docs: cached input is exactly 50% (e.g. gpt-4o $2.50 → $1.25/MTok), so OpenAI cache hits are under-priced **5×** on the estimation path. Cache *creation* is priced at full input rate vs Anthropic's actual 1.25× (under-counted 25%). Mitigation: provider-reported cost wins when available.
4. **Partial assistant text lost on app quit mid-stream** (Low-Medium). Exit calls `cancel_all` → task abort discards the backend buffer (lib.rs:653; send.rs:2071-2073); frontend never gets to persist. User-cancel and error paths are covered (chat.ts:2796-2830 persists synchronously before cancelling).
5. **Checkpoints unbounded per session** (Low). No count-based pruning; refs pruned only on session delete (checkpoints.rs:286-320) — long-lived sessions accumulate git objects.
6. **Worktree orphan window** (Low). `create_worktree` runs before the DB pointer persist (worktree_cmds.rs:86-102); a crash between leaves an unreferenced worktree + branch.
7. **Rollup/budget lag** (Info): aggregates can lag up to 10 minutes behind cost events (cost_v2.rs:192).
