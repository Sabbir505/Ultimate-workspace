## Implementation Plan: Message Order & Artifact Cards

### Root Causes Identified
1. **Double message on `/create`**: `handleSend` called BOTH `onSend` (normal chat turn) and `triggerArtifactGeneration` (artifact proposal)
2. **Cards stacking at bottom**: Proposals render in a global container AFTER the message list, not inline
3. **Parse failures on map→String**: LLMs emit `{"input": {...}}` but Rust expects `String`; schemas had no fallback

### Phase 1: Persist `/create` as Command Message (in progress)
- Add new Tauri command `persist_chat_command_message(chatSessionId: string, content: string, artifactProposalId: string)`
  - Inserts into `chat_messages` with `role='user'` and `content` prefixed `{cmd: artifact}`
  - Returns the persisted message with positive `id` and `createdAt`
- Add IPC wrapper in `src/lib/ipc.ts`
- Modify `triggerArtifactGeneration` to accept optional `messageId` and store on proposal wrapper
- After backend persist, `onDone` will include the message in its merge logic

### Phase 2: Inline Card Rendering
- Extend `ChatView` items array to include proposal-card entries with `anchorMessageId`
- For each proposal where `sourceMessageId` matches a message in `messages`, inject a `proposal-card` item immediately after
- Cards render in document order as part of the virtualized list

### Phase 3: Prompt Template Fix
- Add optional `sourceMessageId?: number` to `ArtifactProposal` interface (TS only, preserved on wire)
- Update `addArtifactProposal` wrapper type to include `msgid?: number`
- Ensure `prompt_template` proposals flow through unchanged (already working after schema fixes)

### Phase 4: Slash Menu Completion
- Unified `SlashItem` type (skill/template/command) already implemented
- `applySlashItem` opens variable-fill for templates with variables
- `/` now shows skills, prompt templates, and `/create` subcommands
