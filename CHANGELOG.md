> **Naming note:** "Relay" is the product name on every surface as of the rename completion (`7f6952b1`, 2026-09-05): user-visible strings (window title, `package.json` name, `tauri.conf.json` `productName`, `<title>`, sidebar/banner/HTML strings), the Rust crate (`relay`, lib `relay_lib`), the bundle identifier (`dev.relay.app`), the sidecar binaries (`relay-browser-mcp`, `relay-automation`), the MCP server identifiers (`relay-browser`, `relay-tools`), the NSIS installer filename, the mobile app (`Relay Mobile`, `com.relay.mobile`), and the Windows scheduled-task name (`RelayAutomations`). ## [0.7.0] — 2026-10-07

**A feature release covering 96 commits since 0.6.0** — the agent stops living inside the transcript. It can now drive the browser pane and Relay's own interface (computer use, phases 0–2), the roles it kept re-describing in prose become a registry it can read and write (Subagents), every project grows a generated wiki whose freshness is computed from git rather than guessed, answers speak as they stream and the vault reads itself aloud, local models get a request log and a loopback gateway, and the phone reaches desktop parity — steering queued sends, peeking at diffs, mirroring a terminal — on an overhauled relay. Alongside: fork-to-panes, browser full screen, a skills gallery, a live MCP registry, Qwen-Image Turbo, an embedding-model picker, the 2026-10-03 audit remediation (9 critical / 43 high / ~110 medium findings), and two black-box E2E suites.

### Added
- **Computer use, phases 0–2 — the agent drives the browser pane, and Relay itself** — six ops that existed as `relay-browser` MCP tools but were unreachable from a chat turn (`browser_find`, `browser_zoom`, `browser_press_key`, `browser_fill_form`, `browser_select_option`, `browser_batch`), plus dual-mode targeting: `click`/`type` accept x/y viewport pixels for the canvas, chart and map content the element tree cannot name — the pixel path hit-tests via `elementFromPoint`, climbs to the nearest interactive ancestor and reports what it actually hit, so a misjudged pixel is debuggable instead of silent, and typing by coordinate focuses rather than clicks so it cannot submit the form it is filling. `browser_batch` validates every step before running any (a typo in step 9 must not leave step 0 applied) and reports every step, including after a failure. Phase 2 is **Relay self-control**: the app's own React DOM is addressed with the same ref contract as the browser pane (`bridge_refs.js` is now its single definition, replacing three hand-synced copies, so a ref cannot mean different things on the two surfaces), refs survive layout shifts and are readable back, elements under `data-relay-agent-exclude` are filtered *before* numbering so a ref can never silently resolve into excluded chrome (the composer's Stop button and the approval dialog are marked), typing uses the native value setter so React registers the change and never submits, and an orphaned ref returns an explicit `stale_ref` telling the model to re-read. Phase 0 is the safety floor this rides on: the tool loop is capped (500 iterations, 1000 in research — `MAX_TOOL_ITERS` was `usize::MAX`, which made the existing "stopped after reaching the tool-call limit" exit unreachable), and `run_code` now answers permission exactly like `run_shell` with an approval card that shows the snippet and says there is no sandbox — it had been falling straight through to `execute_tool` with no card in any posture while `codeexec::sandbox_available` is hardcoded false, i.e. an ungated path to the same host control.
- **Declarative subagents — named agents in a registry, spawnable from the Task tool, a Run button, Session Mesh and automations** — user-defined agents (prompt body, tool allowlist, permission scope, engine/model, worktree policy, spawn budget) stored in a `subagents` table with the 7 builtin roles seeded as data carrying their exact prompts, so nothing changes for users who never open the panel; managed in Settings → Subagents. Spawn surfaces: the `Task` tool (dynamic role enum + explicit `agent` arg — enforced tier: schema filter, execution check, project-root write scope, policy filtering), a manual **Run** button (`run_subagent` — the run is a normal keep-chatting session tagged with the agent), Session Mesh `spawn_session` with `agent:<id>` (model fan-out, mesh caps still govern), and automations via `agent:<id>` (engine-resolved, works in the run-while-closed sidecar). Per-agent hook scoping (`origins` on hooks; subagent runs dispatch `agent:<id>`) is the guardrail for harness/ACP engines, whose native tools Relay cannot restrict — the UI badges that tier honestly ("advisory") instead of pretending. Worktree auto-provisioning (`worktree_policy: always`) via the extracted session worktree seam; origin-scoped hook denies verified end-to-end; `.md` export/import (Claude-Code-compatible frontmatter, strict import); `subagent_runs` history; send-time credential pre-flight and per-agent `max_concurrent` budgets. Live-tested against real models: builtin→OpenRouter and harness→commandcode/deepseek tiers.
- **The registry is a link, not a copy — and harnesses can find it** — the Subagents panel lists each harness CLI's **own** native agents discovered on disk and imports them into the registry in one click, harness sessions get a read-only view of the registry (so they can run a named agent without being able to invent one), and rows the model authored are badged "made by agent" via the `subagents.origin` column. One settings surface: the retired sidebar view is gone and the native stores ride the Settings panel, so there is exactly one place an agent is defined.
- **Agents can author the registry** — `list_subagents` rides every main-loop turn, and `create_subagent` / `update_subagent` / `delete_subagent` let the model define, refine, or remove agents on request — approval-carded in every posture (an agent can never exist or vanish without an explicit yes), name/policy validated by the same code the panel uses, builtins and in-flight agents deletion-refused, and the CRUD trio stripped from the relay bridge and subagent registries so a harness is never advertised a tool it cannot dispatch (harnesses run registry agents via `spawn_session agent:<id>` instead).
- **Project wiki — a generated per-project knowledge base whose freshness is COMPUTED, not guessed** — a repo analysis, an LLM outline, and one call per page, where every page ends in a **Grounded-Claims ledger** (claim → repo-relative path + line range + blob SHA). The update pass diffs HEADs, joins changed paths against stored evidence and re-derives only the affected pages — a clean repo costs zero model calls. Engine (`src-tauri/src/wiki/`) carries a single-call fast path, a commit-triggered freshness watcher and a slow sweep; persistence (`wiki_projects` / `wiki_pages` / `wiki_claims`) adds an external-content FTS5 index over title/summary/body (keyword-only by design — pages are short and keyword-dense, raw file content stays in the RAG corpora). The build is dependable in practice: a malformed response is handed back to the same model with the parser's error for one repair round before the two-phase fallback, retries cover the one-pass and outline calls, **×** kills the in-flight CLI call (with a terminal `cancelled` event from every path), the generation bound raised 180s → 600s for CLI context, and permanent failures (credits/quota/auth, observed as exit-0 CLI replies) surface actionable errors instead of "no JSON in response". Delete is one glass confirm popover; the feed is live during a build.
- **Streaming voice — the answer speaks as it generates, hands-free** — read-aloud now rides the token stream instead of waiting for it: a streaming speech feeder voices complete sentences only (markers like code fences and links are never voiced), the opening words are fed mid-sentence with the engine warmed before the answer so the first sound is immediate, and the first spoken chunk is capped at a clause boundary on CPU reads where the engine is slow to start. The **hands-free loop** is a root controller with a composer toggle and a status bar: it listens, yields the turn on extended silence, speaks the reply, and returns to listening — the toggle button itself is the loop status (the wave replaces the bar). **Barge-in** lets a normal voice interrupt a read: the gate calibrates on sounding audio only (it used to confirm on its own speaker echo and kill its own read), pauses to check, ducks the read's volume on a real spike, and covers the whole answer lifecycle — speech interrupts instead of queueing behind the rest of the reply. Live dictation transcript in the composer, level-fed wave, and `[voice]` timeline logging in devtools for debugging the loop.
- **A request log for local models, plus a loopback gateway** — every call to a local model (the llama.cpp sidecars Relay spawns, and traffic other apps route through the new gateway) is recorded with its request and response bodies verbatim, then summarised into token counts, TTFT and throughput — surfaced in a full-page Logs view, with retention and body-cap settings under Local Models. The gateway forwards **bytes** and never re-frames: Ollama streams bare newline-delimited JSON, llama.cpp plain SSE, LM Studio named-event SSE, and a proxy that understood the stream would need three framing paths and corrupt responses the moment one drifted — so it forwards unchanged, keeps a copy, and hands the copy to a normalizer, meaning a bug there can cost a field but never a response, and raw bodies let telemetry be re-derived later. Relay's own turns are captured in-process at the provider wire bodies and at each tool-loop round (one row per model round). Local models also gained per-model **tool-calling badges** (GGUF template scan + tri-state override) and a raw tool-call pane on the Logs page, with the tool loop gated off when the active model explicitly cannot do tools.
- **Fork a chat into side-by-side panes, and Mod+/ for every shortcut** — fork copies a chat's config and live (non-superseded) history into new sessions pinned beside the focused pane (equalized split ratios, 6-pane cap), with entry points in the ⋮ menu, the command palette, and a fork-here glyph on a bubble that truncates the copy at that message inclusive (`fork_chat_session upto_message_id`); forks record a `fork_of:<id>` origin, title `'<original> · fork N'`, and isolate their own worktree like new chats. The **HotkeyOverlay** opens with `Mod+/` (Alt stays exclusive to STT push-to-talk) and lists every binding grouped by surface from the live, override-aware keybinding map — editable-exempt and occlusion-aware.
- **Projects are back — as a second sidebar panel beside the main one** — "Projects" now sits below Vault in the left sidebar; clicking it slides open a dedicated panel (same liquid glass, same collapse animation) listing every project with its chats nested beneath in inbox form. Nested chats are the exact rows Chat History uses, so pin-to-top, rename, mark-unread, export, split-pane drag and the ⋮ menu all behave identically; clicking one opens the chat and follows its project. Each project row carries a **New Chat** button (same composer seeding as the global "+", bound to that project) and a **Stash** toggle that drops the project below a divider at the bottom of the list until unstashed — the stash set and the panel's open state persist in localStorage across restarts. Per project the **5 most recent chats** show, with **Show more** revealing 5 at a time ("Show less" folds back), and pinned chats float above the recents. A folder-plus in the panel header adds a project via the native folder picker, and the empty state offers the same when no projects exist.
- **Multiple vault assets open as TABS, like notes** — the asset pane now carries its own tab strip (the same component as the note strip, so click-to-activate, ✕ / middle-click close, wheel scroll on overflow and drag-to-reorder all behave identically). Previously `openFile` was a plain `assetPath` overwrite: opening a second PDF silently **threw the first one away**, and with only assets open there was no tab UI anywhere (the note head and its strip live in the note-only branch of the layout). Each PDF also remembers its **zoom and page across tab switches** — the viewer unmounts on switch, so without that every switch dumped you back at page 1 at 100%. State is session-scoped, matching the note pane's per-note mode memory. Asset tabs persist in the layout blob alongside note tabs, and Back/Forward restores the whole strip — including tabs opened *after* the snapshot, which going back must not discard.
- **Voice in the vault — read notes aloud and dictate into them** — the vault's note header carries three controls that ride the speech engines the chat composer already used (local Kokoro TTS, whisper.cpp dictation; no new model, no new key, no cloud call). **Read note** narrates the active note, stripping code fences, math, tables and link URLs through the same markdown-to-speech pass chat uses; **read selection** narrates just the CodeMirror selection and stays disabled until you select something. Dictation writes into the note at the caret through the editor's own transaction path, so it autosaves and undoes exactly like a keystroke, and hold-**Alt** works as push-to-talk. `Mod+Shift+R` / `Mod+Shift+V` and two command-palette entries cover both from the keyboard. Reads stop when you switch notes rather than narrating a note you can no longer see.
- **Browser full screen, one keystroke** — the pane pins itself (`position:fixed inset:0`), the existing ResizeObserver pushes the matching rect through `browser_set_bounds`, and F11 / the URL-bar button / the palette toggle it while Esc exits. A full-screen pane keeps its slot mounted and owns the one visible-webview slot; collapsing the panel or switching the Browser tab drops full screen rather than stranding the user.
- **Skills gallery and MCP registry — install capabilities from inside the app** — a full-width gallery of skills with install-from-URL (raw, GitHub blob/tree, or zip; zip-slip guarded, live-tested against `anthropics/skills`) plus version and allowed-tools metadata, and a live MCP registry with debounced search, status badges and one-click install for allowlisted runtimes (a gallery install keeps the exec gate). The model-market sort controls now actually work (search no longer drops `sort`/`direction`, and Trending maps to HF's `trendingScore` instead of 400ing as `likes`), and Google sign-in and the inverted load spinner were fixed alongside.
- **Replay-proof mobile pairing** — pairing moved to a per-connection `PairChallenge` with an HMAC nonce-bound proof (v2 flag) while keeping a legacy-compat path, a strict-pairing toggle, and a 5-per-60s lockout; the `@noble` cross-implementation vector is pinned so the desktop and the phone cannot drift.
- **The prompt firewall, confirm-edits, and AGENTS.md** — an instruction-injection scanner over every memory/RAG injection point with flag/strip/off modes (Settings → Memory); a `confirm_edits` approval posture whose review cards are computed from the real file with occurrence-level detail and partial accept applying only the kept occurrences; and `AGENTS.md` layered into both harness bundles and the chat system prompt (ancestor discovery, 8k cap) with `read_agents_md` / `write_agents_md` registry tools.
- **Automation templates — a PR-review bot and a repo digest, prefilled** — packaged automation loops reachable from the Automations empty state, a header toggle and the PullsPanel, so the most-wanted scheduled jobs start from a real prompt instead of a blank form. Native search landed too: opt-in Anthropic server-side `web_search` (server tool-use blocks echoed verbatim, with a live-web flag for the tripwire) and OpenAI's native search.
- **Qwen-Image Turbo, and packs that say which components pair** — a new `qwen-image-turbo` package (Viggle's distilled turbo, Q5_K_M + Q4_K_M, its own Qwen3-VL-8B encoder and Qwen-Image 2.1 VAE, 4 steps / cfg 1.0 / 1024px native) with catalog filenames matching the manual pack layout so existing files are reused rather than re-downloaded. Component resolution is family-aware (a family's own encoder/VAE on disk beats the role-generic catalog order, so two families sharing the text-encoder role can no longer cross-pair silently), manually downloaded splits get a **Recommended** badge tagging the same-folder encoder/VAE, and the managed sd.cpp engine pin moved master-872 → master-890 because 872 predates Qwen-Image 2.1 ("get sd version from file failed" — the silent GPU-idle image-gen failure).
- **An embedding-model picker with auto-discovery** — Settings → Knowledge gains an Embedding model card: every embedding GGUF found in the model scan dirs, grouped by family × quantization, backed by a `docs.embedding_model` setting (empty = auto, nomic-embed preferred). Switching restarts the sidecar and rolls back if the new model fails to load; the list re-scans fresh so new downloads appear without leaving settings, and a vanished file falls back to auto with a visible warning. The architecture check learned the `*-embedding*` decoder-embedders (EmbeddingGemma 2) and `*embed*`-named files with chat-arch headers (Qwen3-Embedding); the suggestion sheet filters `mmproj` projectors, badges key off disk discovery, sizes come from HF's `gguf.total` param count (embeddinggemma-2 Q8_0 was shown at 149 MB vs a real 310 MB), and Unsloth UD-*_K_XL dynamic quants are recognized.
- **Attachments render as themselves** — an image attachment is now the picture itself: no bordered card, no filename row, no extension pill (the name lives in the tooltip/alt, the model still sees it in the message body). Caps stay modest (320×240) so a batch of screenshots wraps like a gallery row; docs and text keep their name in a quiet glyph + name row with a clamped content preview. An image whose bytes are gone keeps a dashed tile + name so the gap stays identifiable, uploaded images persist across restarts, and inline artifacts got a fixed height that scales to fit.

Everything in the toolbar scope is a compaction (the caption's content box is 28px and `--toolbar-h` derives from it), and a `:has()` rule collapses the chat spacer while the slot is occupied so left groups still drag the window.
- **Session Mesh phase 4 and the Improvements P3 set** — `mesh_message` / `mesh_turn_complete` lifecycle hooks (detached, PreTrusted), a Mesh settings panel and eval scenarios; flaky-case quarantine, cross-artifact pack health, and per-artifact cost attribution on the cost dashboard. Hybrid RAG got contextual chunk enrichment (path · heading trail embedded alongside content, chunk-schema v2 forcing a re-chunk) and the reranker stage judges docs in their section context.

A **mobile** suite drives the phone app in Expo Go over USB via `adb` (uiautomator dumps + input taps + screenshots) with 37 tests across six suites — core pairing round-trip, chat streaming, every drawer/Settings destination on real relay data, depth inside each section, resilience, and BUGS.md regressions. ### Changed
- **Dictation engine extracted into a shared core** — the mic capture, silence-gap segmentation, serialized commit chain and cancel semantics now live in `lib/voiceDictationCore.ts` behind a small `DictationTarget` interface, with thin adapters for the chat `<textarea>` and the vault's CodeMirror view. The chat path is behaviorally unchanged; the concurrency that used to be welded to a textarea (and would otherwise have been forked a second time) now exists once. The "never clobber what the user typed inside the dictated span" rule is a named, unit-tested function rather than an inline condition.
- **The entry bundle sheds the markdown pipeline, and the past-runs table virtualizes** — react-markdown and the remark/rehype family (including KaTeX) load behind `React.lazy`, dropping the entry chunk from 1,182 KB to 751 KB (gzip 364 → 234 KB) with zero markdown modules left in it; plugins are imported inside the lazy module so no call site can hoist them back, and `MessageBubble`'s unused parser imports are gone. `AutomationRunTable` windows rows with `@tanstack/react-virtual`, so its 1 Hz elapsed timer re-renders ~20 visible rows instead of the whole history (verified with a 500-run windowing test).
- **Pane drops auto-fit the axis instead of refusing** — splitting a pane halves it, so a drop on a too-small pane used to bounce with a toast even though the room sat in its siblings; the drop handler now measures the pane and the grid, re-flows the axis toward the new pane (equal leaf-count shares along the path) and predicts the resulting size. Only a window genuinely too small for another usable pane still refuses, and ratios are untouched when the drop already fits.
- **Local models warm every way they start, and the prompt cache actually holds** — diagnosed from an 83s first-turn TTFT with zero cache hit (turn 2 read 13,769 cached tokens in 0.58s): Settings → Local Models → "Use model" started the sidecar without the prompt warmup only the chat picker had. `cache_prompt` is now sent explicitly on the tool-loop and plain streaming wire bodies and the warmup (LocalGguf only — cloud endpoints reject the field), the sidecar spawns with `--cache-reuse 256` for KV reuse past mid-history divergence (with the generalized optional-flag retry for older binaries), and one shared frontend warmup helper warms under the spinner on every start surface; the send-path respawn's fire-and-forget warmup was removed because continuous batching across llama-server's four auto-slots made it race the in-flight request.
- **The local-model context meter tells the truth** — it resolved the window from a "Context slider" whose setter was never called, so every local model read as a flat 16k (a 16 GB+ GGUF running at 8k showed half-full while actually full and already compacting). The sidecar's real `n_ctx` was on the wire via `local_model_status` and simply discarded; it is now published to the store, with a size-tier prediction mirroring the backend's `auto_ctx_size` for the window before the sidecar is up.
- **Navigation and shell consolidation** — a single back arrow on the full-page views (logs / automations / vault) replaces the previous forward/back pair; the log detail's model moves into the header with a basename chip and wrapped sizes; the MCP registry badge is right-aligned; the skills gallery is a full-width grid; the watcher never cold-starts the embedding sidecar; and the boot sweep reaps orphaned sidecars.

### Removed
- **The vault's "Recent" list** — the recently-opened-notes shortcut strip above the files tree is gone, along with its `recentPaths` store field, its 12-entry cap, and the `relay.vault.layout` persistence key. **Pinned** notes are unaffected and keep the same UI. A stale `recentPaths` entry left in an existing layout blob is simply ignored on load.
- **1,183 lines of unreachable code** — `DocumentsLibrary.tsx` (mounted nowhere, in no shipped bundle), the pre-Projects-sidebar `ProjectItem`/`SessionRow` leftovers (kept green only by their own unit test), the `SHOW_FAKE_UPDATE` flag pinned to `&& false` (its branches unreachable in every build while sitting in shipping `App.tsx`/`Sidebar.tsx` paths) with `seedFakeUpdate`, and the never-called `ensureBrowserTabs` — all deleted with their orphaned CSS.

### Fixed
- **Full audit remediation — 9 critical, 43 high, ~110 medium findings** — end-to-end remediation of `CODEBASE_AUDIT_2026-10-03.md` (a 26-scope review of ~350K lines). Critical: a nested DB-lock deadlock on project-bound sends; the subagent move/copy sandbox gate reading the wrong arg keys; skills zip-slip via backslash separators; worktree pointer validation; whisper sidecar pipe drain; vault autosave path binding; **search API keys moved to the OS keychain**; voice capture re-entrancy; and mobile v3 pairing binding the E2E salt to the connection challenge. High and medium waves swept approval threading, stream block-index clamps, PTY read throttling, background shell byte caps, PDF print CSP and `about:blank` teardown, doc-design slot panics, xlsx row/merge clamps, import zip caps, nested-transaction deletes, the stale automation-run sweep, MCP timeouts, `file://` scope containment, composer per-session reset, the approval Enter-on-Deny path, popout notification dedup, app-lock persistence, spawn_blocking discipline, unbounded-output caps, LIKE escapes, and a dedup wave (`FTS prefix_query` + `escape_like`, catalog downloads, HF filename sanitization, `truncate_to_cap`) — every finding annotated with its location in the audit doc. A follow-up review of that remediation found 19 more defects, four of which actively broke things: **the tag-triggered release workflow aborted on `REF_NAME: unbound variable` on every tagged release** (step-scoped env read from a later step — no signing, no `latest.json`, no GitHub Release; the variable is hoisted to job level now), the automation sweep set `status` on a table whose column is `outcome` (swallowed by `let _ =`, so mirrored rows never closed and silently dropped out of the failure-rate stats), the MCP bridge advertised `unlocked_registry` while dispatching `ToolCaps::default()` (any advertised tool could fail at call time), and browser `file://` containment was wired only into pane CREATE while `prepare_navigate` used the scheme-only validator.
- **Automations: a DB deadlock that froze the app, silent delete confirms, and a stale list** — `delete_automation` and `set_automation_enabled` held the `DbState` mutex guard across `sync_fs_watchers`, which takes the same non-reentrant lock: the row write committed, the command never returned, and **every later DB query in the app parked until restart**. Both commands now scope the write's guard, matching create/update. Separately, `window.confirm` is rejected by this WebView2 build (a rejected Promise is truthy), so every `if (window.confirm(...))` guard silently passed — automation, theme, MCP, knowledge and vault deletes ran with no prompt at all; all are replaced by an in-app confirm (`state/confirm.ts` + `ConfirmDialogHost`). The list also refreshes honestly now instead of showing stale rows.
- **Harness turns stop wedging** — a dead stdout pipe no longer panics the stderr logger (one panic used to wedge every subsequent turn); per-turn CLIs (commandcode/kimi/pi/omp) that print their terminal frame but never exit are killed by a generation-guarded watchdog after a 5s grace so EOF runs the normal completion path with the full reply; `claude_code`'s live ELAPSED counts from prompt-send rather than first event; the on-disk session probe can no longer cross-attribute two panes in the same cwd; a self-healing turn guard recovers the session's turn counter after a crash; and crash-proof process trees mean stopping a run cannot orphan children. Native permission modes ride per-turn argv for kimi (yolo/auto/plan), omp (always-ask/write/yolo) and commandcode (standard/plan/accept-edits), with pi/opencode gaps surfaced as a note in the composer instead of a silent no-op; the relay bridge maps the subagent tool family so advertised tools are routable; and RAG indexing works end to end (immediate index on corpus add, normalized `\\?\` UNC paths plus a migration, `--ubatch-size` matched to the sidecar's context — the 512 default rejected ~600-token chunks — oversized files retried with head truncation instead of aborting the run, and a panicked index can no longer leak the "already in progress" slot).
- **The gateway's own audit** — request-log bodies were being truncated and retention never ran; both fixed, together with the clippy 1.97 `sliced_string_as_bytes` in the gateway test.
- **Voice repairs from live use** — barge-in calibrates on speaker echo instead of killing its own read, then pauses and checks before ducking; the hands-free toggle actually turns off (the mode flip happens on exit); a read that dies before sounding recovers the loop and says why; GPU streaming batches flush on time so the queue never starves behind a spawn; and a send during a still-silent turn auto-cancels that turn instead of queueing behind it.
- **Local-model and download correctness** — compaction audited end to end (the phantom context window, "Compact now" budgeting against the full window with `reserved_tokens = 0`, and an over-budget summarizer are all fixed), a local session's model name and real context window are reported correctly, and the agent's download cards now leave the chat (completed tasks fade out; failed/cancelled ones stay until clicked, and failures are announced once instead of four times) while healthy transfers are no longer killed.
- **Phone-turn reliability** — `session_chat.rs` self-deadlocked re-locking `DbState` while holding it (`artifacts_dir()` inside the fs_roots block), parking every phone-originated send at "5d: fs_roots start" with a blank desktop UI; the phone's render loop issued ~60 req/s of List* queries that starved the desktop's DB mutex (now coalesced and rate-limited to 0.6/s); wire timestamps (`started_at`/`completed_at`) were dropped by the protocol so "Worked for Xs" always fell back to a plain "Worked"; and a snake_case→camelCase mismatch at the relay boundary left timestamps, artifact chips and token counts silently undefined. On the phone, tool-call rows are now one static line (the expand arrow opened an empty sheet — phone payloads carry no code/edit bodies) and the ten redundant-trailing-semicolon `step_trace` warnings are gone. - **Subagents and the registry, audited** — an audit pass over the feature (9 defects) plus the gaps they pointed at: automations routed the engine label ("builtin") as the API provider and let an unparsed `provider::model` ride through (provider/model resolution is one shared helper now); harness-engine agents fell through to the chat-HTTP arm because `harness:commandcode` is not a bare id (the automation router strips the prefix and ACP-engine automations fail with a clear "no unattended path" error); the markdown export scrambled the tool allowlist order (it rode a `HashSet`); and the registry rename could deadlock startup on a pre-rename database.
