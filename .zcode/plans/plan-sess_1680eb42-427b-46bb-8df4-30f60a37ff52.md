This is a large feature. I'll implement it in phases, starting with the highest-value items that build on existing infrastructure. Each phase is independently testable.

## Phase 1: Toolbar tabs + GitHub pill (UI shell + existing-content wiring)

**Goal**: Add the tab buttons to the top-right toolbar and the GitHub pill beside the project pill. Wire the tabs that map to existing content immediately; stub the new ones.

### 1a. Toolbar tabs (`App.tsx`)
In the toolbar's right cluster (before the toggle-panel button), add a row of compact tab buttons:
- **Changes** → opens the existing DevDiffPanel (rename of the current "Files" tab).
- **Branch** → opens the new Branch panel (Phase 2).
- **Commit** → opens the new Commit/Push panel (Phase 3).
- **Plans** → opens the new Plans view (Phase 4).
- **Progress** → opens the existing task-progress data (Phase 4).
- **Terminal** → calls `setToolPanelTab("terminal")` + opens the ToolPanel (existing).
- **Agent** → focuses the composer's agent menu (existing).

Each button calls `useUiStore.setToolPanelTab(id)` + `setToolPanelCollapsed(false)` to reveal content in the right panel. Style: compact pill-buttons using the existing `.toolbar-icon-btn` pattern or a new `.toolbar-tab` class.

### 1b. Extend `ToolPanelTab` union (`src/state/ui.ts`)
Add: `"changes" | "branch" | "commit" | "plans" | "progress"` to the existing `"terminal" | "browser" | "files" | "canvas"` union. Rename the "Files" tab label to "Changes" (same DevDiffPanel content).

### 1c. GitHub pill (`ChatComposer.tsx`)
Insert a `GitHubNotch` component right after `<FolderNotch />` in the `composer-context-meter-wrap`. It shows a GitHub icon + the current branch name (from `GitStatusInfo.branch`). Clicking it opens the Branch panel in the ToolPanel. CSS mirrors `composer-notch-folder`.

## Phase 2: Branch switcher (new backend + panel)

### 2a. Backend: git branch commands (`src-tauri/src/git.rs` + `git_cmds.rs`)
New functions + Tauri commands:
- `git_list_branches(path)` → `Vec<BranchInfo>` (name, is_current, is_remote, last_commit_msg). Parses `git branch -a --format='%(refname:short)|%(objectname:short)|%(contents:subject)'`.
- `git_create_branch(path, name)` → creates + checks out a new branch (`git checkout -b`).
- `git_checkout_branch(path, name)` → switches branch (`git checkout`).
- `git_delete_branch(path, name)` → deletes a local branch (`git branch -d`).
- Register all in `lib.rs`.

### 2b. IPC (`src/lib/ipc.ts`)
Add wrappers: `listGitBranches`, `createGitBranch`, `checkoutGitBranch`, `deleteGitBranch`.

### 2c. Branch panel component (`src/components/panes/BranchPanel.tsx`)
- **Search bar** at the top to filter branches.
- **Branch list** — each row: branch name, current-branch indicator, last commit message. Click to checkout.
- **"Create new branch" button** — prompts for a name, creates + switches.
- **Git graph** — a simplified `git log --oneline --graph` rendered as a compact vertical list with branch-merge lines. (Full graph rendering is complex; I'll start with a `--oneline` list with merge indicators and iterate.)
- Polls branches every 5s.

## Phase 3: Commit/Push panel (new backend)

### 3a. Backend: git commit/push commands (`git.rs` + `git_cmds.rs`)
- `git_stage(path, files)` → `git add <files>` (or `git add -A` if empty).
- `git_commit(path, message)` → `git commit -m "<message>"`.
- `git_push(path, remote?, branch?)` → `git push` (auto-detects upstream).
- `git_get_remote_url(path)` → returns the origin URL (for the GitHub pill link).
- Register all in `lib.rs`.

### 3b. Commit panel component (`src/components/panes/CommitPanel.tsx`)
- **Staged/unstaged file list** (reuses `getChangedFiles`).
- **Commit message textarea**.
- **Stage All / Commit / Push buttons**.
- Shows current branch + ahead/behind counts.

## Phase 4: Plans + Progress tabs

### 4a. Progress tab
Reuse the existing `chat:task-progress` data from `useChatStore(s => s.tasks)`. Render a dedicated panel (`src/components/panes/ProgressPanel.tsx`) listing all tasks for the active chat session with their status/progress bars — same data as the inline `TaskProgressCard` but in a dedicated panel.

### 4b. Plans tab
Extract the model's plan/outline from the conversation. The simplest approach: render a structured view of the assistant's tool-call sequence (the steps the agent took) as a "plan" timeline. This reuses existing message data — no new backend needed. A richer version would parse explicit "plan" structures from the assistant's responses.
